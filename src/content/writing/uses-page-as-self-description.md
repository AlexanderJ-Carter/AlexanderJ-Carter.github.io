`/uses` 这类页面在独立站点圈很常见：编辑器、键盘、相机、主机商列成清单。做得差时像未打码的购物小票；做得好时像一份简短的工程文化说明——你如何工作，以及你愿意维护什么复杂度。

## 访客为什么要点进来

- 好奇站点技术栈，想复现类似搭建；
- 看重隐私与性能的人，想确认你是否言行一致；
- 潜在协作者快速判断协作成本。

所以 Uses 应回答「为什么这样选」，而不只是「我买了什么」。

## 我怎么分组

本站大致分开：

- **站点本身**：Astro、Tailwind、部署与 CDN；
- **写作与设计**：编辑器、字体、图片流程；
- **设备**：只列真正影响产出的，避免年度旗舰晒单。

每组用几句话说明取舍。例如：选择静态生成，是因为更新节奏与内容形态匹配；选择某字体，是因为中文阅读与标题气质。

## 更新策略

换电脑不必立刻改页；换构建链或分析工具应尽快改——这和隐私政策同步的原则一样。过期 Uses 会让人怀疑其他页面的可信度。

季度回顾一次足够。删掉不再用的工具，比追加更重要。

## 与 About 的分工

- About：人是谁、关心什么、如何联系；
- Uses：手艺的材料与约束；
- Projects：做出来的东西。

三页互相链接，但不互相粘贴长文。访客应能在两分钟内建立心智模型。

## 小结

Uses 页是低调的信任工具。写短、写真、写取舍，让它成为站点技术伦理的缩略图。装备会贬值，说明「我为何用这些东西工作」的句子更耐放。
