`/uses` 這類頁面在獨立站點圈很常見：編輯器、鍵盤、相機、主機商列成清單。做得差時像未打碼的購物小票；做得好時像一份簡短的工程文化說明——你如何工作，以及你願意維護什麼複雜度。

## 訪客為什麼要點進來

- 好奇站點技術棧，想復現類似搭建；
- 看重隱私與效能的人，想確認你是否言行一致；
- 潛在協作者快速判斷協作成本。

所以 Uses 應回答「為什麼這樣選」，而不只是「我買了什麼」。

## 我怎麼分組

本站大致分開：

- **站點本身**：Astro、Tailwind、部署與 CDN；
- **寫作與設計**：編輯器、字體、圖片流程；
- **設備**：只列真正影響產出的，避免年度旗艦曬單。

每組用幾句話說明取捨。例如：選擇靜態生成，是因為更新節奏與內容形態匹配；選擇某字體，是因為中文閱讀與標題氣質。

## 更新策略

換電腦不必立刻改頁；換構建鏈或分析工具應盡快改——這和隱私政策同步的原則一樣。過期 Uses 會讓人懷疑其他頁面的可信度。

季度回顧一次足夠。刪掉不再用的工具，比追加更重要。

## 與 About 的分工

- About：人是誰、關心什麼、如何聯繫；
- Uses：手藝的材料與約束；
- Projects：做出來的東西。

三頁互相連結，但不互相貼上長文。訪客應能在兩分鐘內建立心智模型。

## 小結

Uses 頁是低調的信任工具。寫短、寫真、寫取捨，讓它成為站點技術倫理的縮略圖。裝備會貶值，說明「我為何用這些東西工作」的句子更耐放。
