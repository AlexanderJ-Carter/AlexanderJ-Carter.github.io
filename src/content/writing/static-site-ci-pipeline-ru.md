Типичная авария личного сайта: правка i18n локально, забытый build, push — Pages сломаны в метро. CI не делает креативнее — заставляет падать раньше.

## Минимальный pipeline

1. Чистая установка (lockfile)
2. `astro check`
3. `npm run build`

Потом: link check, Lighthouse, preview. Не десять бейджей до зелёной сборки.

## Почему локально недостаточно

- Другая версия Node
- Регистр путей на Linux CI
- Забытые generated-файлы или env
- Ошибка только на одной локали

CI на чистом Linux — страховка для будущего себя.

## Разделить check и deploy

PR: доказать сборку. `main`: публикация после зелёного. Логи должны называть страницу / запись collection.

## Не превращать в декор

Секреты в логах = публично. Бессмысленные ежедневные сканы = игнор красного. Коротко, стабильно, по реальному риску.

## Плюс для студента

После паузы CI говорит, жива ли ветка, прежде чем вспоминать контекст.

## Итог

Для Astro-сайта часто хватает трёх шагов. Автоматизируй привычку, которую и так делал бы — без театра.
