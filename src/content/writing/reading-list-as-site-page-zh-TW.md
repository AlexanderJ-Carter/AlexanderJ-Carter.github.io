很多人把「在讀」塞進社群媒體動態，幾天後就翻不到了。我更想要一頁能夠慢慢長的閱讀清單：路線清楚、筆記可尋、過期的書敢拿掉。

本站的 `/reading-list` 就是為這件事存在的。它不是電商榜單，也不是 affiliate 漏斗，而是一份給未來自己看的地圖。

## 書單頁解決什麼問題

1. **減少重複踩坑**：同類主題讀過什麼、為什麼棄讀，寫下來下次少糾結。
2. **讓推薦可驗證**：別人問「學 Web 讀什麼」時，能指到一條有順序的路線，而不是隨口丟三本暢銷書。
3. **把閱讀接回創作**：攝影書、工程書、散文，最後應能回流到寫作與畫廊，而不是停在高亮句子裡。

如果一頁書單只有書名和星星，它和購物車差別不大。有價值的部分是：**你為何把它放進這條路線，以及讀完後世界有什麼變化。**

## 結構：路線 > 條目 > 感想

我用三層：

- **路線**：例如「靜態站工程」「觀察光線」「長期寫作」。每條路線有一段說明，告訴訪客起點與終點。
- **條目**：書名、作者、狀態（在讀 / 讀完 / 擱置）。
- **感想**：短則一段，長則多段；允許不完整，但必須具體。

感想裡我強迫自己寫「可執行的一句」：比如「讀完後我把首頁第一屏的統計條刪了」，而不是「啟發很大」。

## 敢刪，是書單可信的前提

擱置與移出公開列表，和選片刪照片一樣重要。繼續掛著「計畫讀」卻三年不動的書，會污染信任。寧可列表短，也不要假裝博學。

季節變化時回顧一次：哪條路線還在走，哪本被新認知取代。個人站允許慢，也要求誠實。

## 和寫作、專案的交叉引用

理想狀態是：

- 讀效能書 → 寫出效能實踐文 → 改站點建置；
- 讀攝影書 → 改選片標準 → 更新畫廊說明；
- 讀設計書 → 收緊色板與字階。

閱讀清單頁因此成為索引，而不是孤島。若你只有書單沒有創作出口，書單會慢慢變成博物館展簽。

## 實作上保持無聊

Markdown 或結構化資料皆可；關鍵是能進 Git、能多語言、能靜態產生。不要為了「書單社交」引入必須登入的複雜應用。本站選擇可維護的資料形狀，把時間留給閱讀本身。

## 避免的兩種書單病

**收藏癖：** 只加不減，列表變成身份裝飾。症狀是「想讀」遠多於「讀完」，且感想欄長期空白。

**清單癖：** 每本書只剩星級與標籤，讀起來像資料庫匯出。沒有句子說明「它改變了站點的哪一處決策」，讀者無法複用你的經驗。

解藥仍是那句：可執行的感想 + 定期刪除。

## 小結

把閱讀清單做成一頁站，是在對抗資訊流的健忘。路線、條目、可執行感想，再加上敢於刪除——這就夠了。它不會讓你看起來更忙，但會讓你的站點更像一個長期運轉的大腦，而不是裝飾性的外連牆。
